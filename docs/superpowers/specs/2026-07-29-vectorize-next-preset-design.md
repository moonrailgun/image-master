# 图片矢量化：下一个预设并生成

## 目标

在图片矢量化设置中，为需要连续试验多个预设的用户提供单击操作：切换到下一个预设，并立即使用该预设生成结果。

## 交互设计

- 在“预设风格”下拉框右侧放置一个方形循环按钮。
- 按钮通过循环图标和 tooltip 表达“下一个预设并生成”。
- 点击按钮后，按 `PRESET_LABELS` 的现有展示顺序选择下一个预设。
- 当前预设是最后一项时，下一个预设回到第一项“默认”。
- 下拉框立即显示新的预设，同时开始矢量化。
- 矢量化进行中禁用循环按钮，与现有“开始矢量化”按钮保持一致，避免多个任务并发覆盖结果。

## 行为范围

- 普通下拉框仍然只切换预设，不自动生成。
- 现有“开始矢量化”按钮行为不变。
- 如果“自定义参数”已开启，循环生成继续使用当前自定义参数；新预设只替换预设部分。
- 如果生成失败，保留已切换到的新预设，并复用现有错误提示。
- 没有已选图片时不会展示设置面板，因此不需要为循环按钮增加单独的空文件提示。

## 实现设计

将预设顺序收敛为从 `PRESET_LABELS` 派生的有序列表，并提供一个纯函数计算下一个预设。该函数负责普通前进、末尾回绕，以及当前值不在列表中时回退到第一项。

扩展现有生成入口，使其可以接收一个可选的本次预设：

1. 普通“开始矢量化”不传参数，继续读取当前预设。
2. 循环按钮计算下一个预设。
3. 循环按钮更新 React 状态，让下拉框显示新值。
4. 循环按钮将新预设直接传给生成入口。

直接传递新预设可以避免 React 状态异步更新导致本次生成仍使用旧预设。生成、进度、结果更新和 toast 仍复用同一条流程，不复制业务逻辑。

## 错误与并发处理

- 循环按钮在 `processing` 为 true 时禁用。
- 生成异常继续由现有 `try/catch/finally` 处理。
- 无论成功或失败，`processing` 最终恢复为 false。
- 不引入任务队列、取消操作或结果历史；这些不属于本次快速切换需求。

## 测试与验证

自动化测试覆盖纯预设循环逻辑：

- 从任意非末尾预设前进到下一项。
- 从最后一项回绕到第一项。
- 未知当前值回退到第一项。

实现完成后运行：

- 相关 Bun 测试，确认预设循环行为。
- 全量测试，确认没有回归。
- ESLint，确认代码规范。
- Next.js 生产构建，确认类型检查和构建通过。
